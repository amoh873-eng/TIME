# ⚖️ Attendance & Auditing API — ASP.NET Core (.NET 9)

API ويب إنتاجي قابل للتوسّع لأتمتة مراجعة الحضور، الإجازات، المغادرات، التأخير، الإجازات المرضية، والمكافآت — **لأكثر من 2 مليون سجل** — بناءً على أنظمة الخدمة المدنية الأردنية (المواد 97–119، تعليمات الحضور 2020، أنظمة الموارد البشرية 2025/رقم 33).

---

## القواعد القانونية المنفّذة (بدون أي إغفال)

| المرجع | القاعدة |
| --- | --- |
| **المادة 118/ب** | الاستئذان الذي يتجاوز 4 ساعات في يوم واحد → خصم **1.0 يوم** من رصيد الإجازة السنوية |
| **المادة 118/ج** | التجميع الأسبوعي لدقائق التأخير/الانصراف المبكر **داخل ساعات الدوام الرسمي (08:30–15:30 = 7 ساعات / 420 دقيقة)**: إذا بلغ مجموع دقائق أسبوع الموظف **60 دقيقة أو أكثر** (الحدّ وأيام الخصم قابلة للتخصيص من «إعدادات المادة 118/ج») → خصم **1.0 يوم** كامل من الإجازات |
| **المادة 7 (2020)** | عدّ التأخيرات الصباحية شهرياً: `3` = تنبيه خطي، `4` = إنذار خطي، `>4` = حسم يومين من الراتب |
| **قاعدة 15 يوماً** | إجمالي الغياب الشهري `> 15` يوماً (سنوية+مرضية+118/ب+118/ج) → **خصم 50%** من المكافأة، وإلا 0% |
| **المادة 112** | نسب الإجازة المرضية: `1–120` يوم = 100%، `121–240` = 75%، `241–360` = 50%، بلا ترحيل للسنة التالية |
| **المواد 100/د، 101، 105** | Pro-Rata للموظف الجديد `((12-شهر+1)/12)×30`؛ منع التراكم لأكثر من **سنتين**؛ سقف تعويض نهاية الخدمة **60 يوماً** |
| **المواد 4/أ + قواعد** | البديل إلزامي؛ إشعار مسبق ≥ يوم واحد؛ فصل `IsEffective` عن `IsApproved`؛ موافقة المدير المسبقة لمغادرات الصباح |

## معمارية القياس والأداء (لـ 2M+ سجل)

- **دفعات غير متزامنة** بحجم 50,000 عبر `System.Threading.Channels` + `BackgroundService`.
- **EF Core 9 + EFCore.BulkExtensions** لعمليات الـ Bulk (إدراج/تحديث).
- **Dapper** لقراءة وجهات التقارير (Views).
- **MiniExcel** لقراءة ملفات `.xlsx`/`.csv` بدفق منخفض الذاكرة + **SqlBulkCopy** لنقل الدفعات.
- **فهارس مركبة**: `IX_Attendance_Employee_Date`، `IX_Attendance_Employee_Month`، `IX_Attendance_Employee_Week`.
- **إجراء مخزّن** `sp_process_year_end_rollover` لمحرك الترحيل السنوي.

## التشغيل

```bash
cd d:\TIME\AttendanceApi
dotnet run
```

1. اضبط `ConnectionStrings:DefaultConnection` في `appsettings.json` (الافتراضي: `Server=.\SQLEXPRESS;Database=AttendanceAudit;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true;Command Timeout=300`) — ومهلة الأمر `Command Timeout=300` تُطيل زمن انتظار الأوامر المباشرة (بينها معاملة التنظيف والتقارير الثقيلة) بدل مهلة ADO الافتراضية (30 ثانية) على قواعد البيانات الكبيرة.
2. قاعدة البيانات والمخطط (الجداول + الـ Views + الإجراء المخزّن) تُنشأ **تلقائياً عند الإقلاع** عبر `DatabaseInitializer` — لا حاجة لتشغيل السكربتات يدوياً.
3. افتح الواجهة المبسّطة: `http://localhost:5000/` — أو لوحة المطوّرين: `http://localhost:5000/console.html` — أو OpenAPI: `http://localhost:5000/openapi/v1.json`.

## الواجهة

| الصفحة | الوصف |
| --- | --- |
| `/` (الرئيسية) | واجهة مبسّطة: **ارفع ملف Excel فقط** واستلم تقرير Excel واحد. تنفّذ تلقائياً: الاستيراد (`import?replace=…`) ← المراجعة القانونية (`review`) ← إصدار الملف (`export-excel`)، ثم تعرض ملخصاً شاملاً (الطلبات/الموظفون/أيام 118/ب/أسابيع وأيام 118/ج/تجاوز 15 يوماً) وتوزيع أنواع الطلبات، وتنزّل الملف باسمه من الترويسة `Content-Disposition`. كما تعرض أسفلها **لوحة التزام الإدارات/المديريات** على شكل **مخطط دائري ثلاثي الأبعاد** (Canvas بلا أي مكتبات): الشرائح مرتّبة **تصاعدياً بالمخالفات (الأكثر التزاماً أولاً)** ومقياس الألوان من الأحمر (التزام منخفض) إلى الأخضر (التزام مرتفع)، مع جدول تفصيلي (موظفون/مخالفون/نسبة الالتزام) وتحويم يبرز الشريحة المقابلة وتلميح بالتفاصيل، وخيارات: التجميع (الإدارة الرئيسية/الإدارة)، الترتيب، أدنى عدد موظفين، وعدد الشرائح (+ شريحة «باقي الإدارات»). |
| `/console.html` | لوحة المطوّرين: استدعاء كل نقطة نهاية على حدة مع عرض استجابة JSON الخام (للاختبار والتشخيص). |
| `/punch.html` | **قائمة مستقلة للحضور والانصراف** (لا تمسّ تقارير المغادرات والإجازات): سحب وإفلات ملف البصمات، ثم «معالجة الملف وإخراج النتائج» (رفع ← تحليل قانوني ← تقارير)، مع 17 مؤشراً تنفيذياً (منها أيام العطل الرسمية/الدينية ونهاية الأسبوع والدوام فيها)، لوحة جودة بيانات الملف (توزيع حالات التحضير)، أربعة جداول لأبرز المخالفات (الأيام، الأسابيع ≥ 60 دقيقة، عقوبات المادة 7، التزام الإدارات)، وزر تنزيل التقارير القانونية (16 ورقة). ثم قسم **«قائمة تقارير الحضور والانصراف»**: 14 بطاقة تقرير (كشف الحضور اليومي، التأخير، الانصراف المبكر، المغادرة أثناء الدوام، 118/ب، 118/ج، الغياب، نقص البصمة، الدوام في العطل، تقويم العطل، الملخص الشهري، الإجازات، التزام الإدارات، الملف الكامل) لكل منها **معاينة** داخل الصفحة و**تنزيل Excel مستقل** مع فلاتر (من/إلى/الرقم الوظيفي/سقف الصفوف)، وقسم **«تقويم العطل الرسمية والدينية»** لعرض العطل وإضافتها أو استبعادها أو استيرادها من Excel أو استعادة كتالوج النظام وتنزيل التقويم، وقسم جديد **«إعدادات المادة 118/ج (مرنة)»** لتغيير حدّ الدقائق الأسبوعي وسقف الناتج المحتسب وأيام الخصم وخيارات الدمج وحدّ السماح الصباحي وتجاوزات الإدارات، مع **معاينة أثر الإعدادات قبل الحفظ** وزر **إعادة التحليل الآن** وزر إعادة القيم الافتراضية (بلا إعادة تشغيل الخدمة). وفي أعلى كل الصفحات **قائمة تنقل موحّدة** (المغادرات والإجازات — الحضور والانصراف — تقويم العطل — لوحة المطوّرين). |

**زر الإعدادات ⚙️:** في ترويسة الواجهة الرئيسية، يفتح نافذة **إعدادات الربط المباشر بقاعدة البيانات** (تفعيل الوضع، وضع الاتصال، بيانات الاعتماد، محرّر الاستعلام، حدود القراءة، الأتمتة، أزرار: اختبار الاتصال / معاينة / مزامنة الآن وتحديث اللوحة / حذف كلمة المرور / استعادة الاستعلام الافتراضي، وعرض مسار ملف الإعدادات وحالة آخر مزامنة). وبجانبه **شارة الوضع**: «الوضع: ملف Excel» أو «الوضع: قاعدة بيانات مباشرة» بحسب الإعدادات المفعّلة، مع ملاحظة توضيحية وزر «🔄 مزامنة الآن» داخل الصفحة.

تفاصيل الواجهة المبسّطة: سحب وإفلات أو اختيار الملف (`.xlsx`/`.xls`)، شريط خطوات بحالة كل خطوة (قيد التنفيذ/تم/فشل)، رسائل خطأ عربية واضحة، زر «تنزيل الملف» يعيد التنزيل دون إعادة المعالجة، وزر **«تنزيل التقارير القانونية (10 أوراق)»** يصدر ملف التقارير الاحترافية لكل قاعدة في الوثيقة، وخياران متقدّمان: `replace` قبل الاستيراد و«التنزيل التلقائي». وتعمل الواجهة دون إنترنت ودون أي مكتبات خارجية.

لوحة الالتزام: تُحمَّل تلقائياً عند فتح الصفحة (من بيانات آخر معالجة في قاعدة البيانات) وتُحدَّث بعد كل معالجة، وزر «تحديث المخطط» يعيد الاستدعاء، والمخطط مرسوم بالكامل بـ `Canvas 2D` (قطاع حلقي إهليلجي مُجسَّم بجدار خارجي داكن وجدار داخلي مظلَّل وفتحة وسطية شفافة ولمعة زجاجية).

## مراجعة «تقرير المغادرات» (ملف Excel العربي)

التقرير الصادر من نظام الموارد البشرية يحمل أعمدة عربية:
`رقم الطلب · الرقم الوظيفي · الموظف · من وقت · إلى وقت · من تاريخ · إلى تاريخ · المدة · حالة الطلب · نوع الطلب · تاريخ الطلب · الإدارة · الإدارة الرئيسية`

**الخطوات:** ارفع الملف → راجع → نزّل التقرير:

```bash
curl -F "file=@departures.xlsx" "http://localhost:5000/api/v1/departures/import?replace=true"
curl -X POST "http://localhost:5000/api/v1/departures/review"
curl -o "review.xlsx" "http://localhost:5000/api/v1/departures/export-excel"
```

**قواعد التحويل المطبَّقة:**

- الأعمدة تُقرأ **بالاسم العربي** من ترويسة الملف، مع الرجوع إلى الترتيب (A..M) عند اختلاف الترويسة.
- `المدة` النصية (`(7 ساعات)` / `(1 ساعات / 30 دقيقة)` / `( يوم )` / `(2 أيام )`) تُحوَّل تلقائياً إلى دقائق وأيام.
- الطلب في اليوم الواحد: تُحسب المدة من فارق `من وقت`/`إلى وقت` (الأدق)؛ الطلب الممتد عبر أيام: من نص المدة.
- `الرقم الوظيفي` يُخزَّن **نصاً** لأن القيم تتجاوز حدود `int`.
- تصنيف `نوع الطلب`: `استئذان` (طارئ/طبي) → المادة 118/ب و118/ج، `اجازة- سنوية`/`اجازة- مرضية` → أيام غياب، `رسمية` (مهمة عمل/انتداب/تدريب) → **تُستورد كاملة مع ساعة الحضور وساعة الغياب** لكنها لا تُحتسب غياباً، والحالات غير «مقبول» تُستثنى.
- **118/ب:** كل استئذان يتجاوز 240 دقيقة → خصم 1.0 يوم.
- **118/ج (التأخير الأسبوعي):** دور الدوام الرسمي هو **08:30 → 15:30 (7 ساعات = 420 دقيقة)**؛ ولكل أسبوع ISO (الاثنين–الأحد) يُجمع مجموع دقائق الاستئذانات الواقعة **داخل** هذه النافذة لكل موظف، فإذا بلغ المجموع **60 دقيقة أو أكثر** → خصم **1.0 يوم** كامل من الإجازات.
  - تُستثنى طلبات الاستئذان التي **تجاوزت 4 ساعات** (تُعاقب بموجب 118/ب) لمنع الازدواج، وتُحتسب الطلبات الواقعة في **يوم واحد** والتي لها أوقات متاحة فقط (بدون أوقات لا يمكن قياس التأخير).
  - تُنسب أسابيع الموظف إلى شهر **أول مغادرة محتسبة داخل الأسبوع** لبناء الملخّص الشهري.
  - التجميع الكامل متاح في جدول `DeparturesWeeklyLateness` وعبر `GET /api/v1/departures/weekly-late?jobNumber=...`.
- **المكافأة:** إجمالي الغياب الشهري (سنوية + مرضية + 118/ب + 118/ج) `> 15` يوماً → خصم 50%.
- الجداول: `StagingDeparturesReport` (الصفوف الخام) → `DeparturesReportReviews` (ملخّص شهري/موظف) + `DeparturesWeeklyLateness` (تجميع أسبوعي/موظف).

### «التقارير القانونية الاحترافية» — تقرير مستقل لكل قاعدة في الوثيقة

`GET /api/v1/departures/export-legal-reports` (وبزر **«تنزيل التقارير القانونية (10 أوراق)»** في الواجهة الرئيسية بعد انتهاء المعالجة).

تقرير Excel واحد مبنيّ على نتائج المعالجة نفسها (جدول المرحلة + المراجعة الشهرية + التجميع الأسبوعي)، بتنسيق احترافي: عنوان مدمج، سطر توضيحي بالفترة والمصدر، ترويسة ملوّنة مجمَّدة، حدود، مرشّح تلقائي، سطر إجمالي، وإبراز أيام الخصم بالأحمر. والأوراق هي:

| # | الورقة | مضمونها وقاعدتها |
| --- | --- | --- |
| 1 | الملخص التنفيذي | عدد الحالات والموظفين وأيام الخصم من الإجازات وأيام الحسم من الراتب لكل قاعدة، مع سطر إجمالي |
| 2 | دليل القواعد القانونية | نص كل قاعدة في الوثيقة والعقوبة وأساس الاحتساب من «تقرير المغادرات» (وما يتطلب بيانات إضافية) |
| 3 | المتأخرون 60 دقيقة - 118-ج | كل موظف/أسبوع بلغ مجموع تأخيره وانصرافه المبكر داخل الدوام الرسمي **60 دقيقة أو أكثر** → **خصم يوم كامل من الإجازات** (مع الدقائق، المدة بالعربية، أيام الخصم، والمرجع القانوني) |
| 4 | الاستئذان فوق 4 ساعات - 118-ب | كل استئذان تجاوز **240 دقيقة** → **خصم يوم كامل من الإجازة السنوية** (رقم الطلب، التاريخ، الأوقات، المدة، الإدارة) |
| 5 | التأخير الصباحي - المادة 7 | عدد أيام التأخير الصباحي لكل موظف/شهر: `3` = تنبيه خطي، `4` = إنذار خطي، `>4` = حسم يومين من الراتب |
| 6 | خصم المكافأة - تجاوز 15 يوماً | إجمالي الغياب الشهري (سنوية + مرضية + 118/ب + 118/ج) `> 15` يوماً → **خصم 50%** من مكافأة الشهر |
| 7 | الإجازات المرضية - المادة 112 | أيام الإجازة المرضية لكل موظف/سنة موزَّعة على التدرّج: 100% حتى 120 يوماً، 75% إلى 240، 50% إلى 360، وبلا راتب بعد ذلك |
| 8 | رصيد الإجازة السنوية | الاستحقاق (30 يوماً) − الإجازة السنوية المستخدمة = الرصيد المتبقي، مع حالة الرصيد المنخفض (< 20% من الاستحقاق) |
| 9 | كشف الخصومات المُجمَّع | لكل موظف: أيام خصم 118/ب و118/ج وإجمالها (من رصيد الإجازات)، ومرات حسم الراتب (المادة 7)، وأشهر خصم المكافأة — للتسوية مع الإجازات والرواتب، مرتّباً بالأعلى خصماً |
| 10 | منهجية الاحتساب | خطوات المعالجة، تعريف التأخير الصباحي والانصراف المبكر، منع ازدواج العقوبات، وحدود البيانات (غياب البصمات والأرصدة المُرحَّلة) والمراجعة البشرية |

**ملاحظات احتساب مهمة:**

- **الطلبات المعتبرة:** الحالة «مقبول» فقط مع وجود تاريخ، وبقية الحالات تُستثنى من كل الأوراق.
- **تعريف التأخير الصباحي (المادة 7):** استئذان في اليوم نفسه يبدأ عند **08:30 أو قبله** وينتهي بعده، ولم يتجاوز 4 ساعات؛ و**الانصراف المبكر** هو طلب يبدأ قبل 15:30 وينتهي عند 15:30؛ ويُستثنى المتجاوز لأربع ساعات من عدّ المادة 7 ومن التجميع الأسبوعي لمنع الازدواج مع 118/ب.
- **الأسبوع:** ISO (الاثنين–الأحد)، وتُنسب نتيجته إلى شهر أول مغادرة محتسبة فيه.
- **المواد 100/د و101 و105** (الاحتساب التناسبي للجديد، منع التراكم أكثر من سنتين، سقف تعويض نهاية الخدمة 60 يوماً) تحتاج تاريخ التعيين والأرصدة، لذا تُدرَج في «دليل القواعد» للمرجعية فقط.

### لوحة «التزام الإدارات/المديريات بالقوانين» (المخطط الدائري ثلاثي الأبعاد)

`GET /api/v1/departures/compliance-by-administration?byMainDepartment=true&minEmployees=3`

- **الإسناد التنظيمي:** يُنسب كل موظف إلى الإدارة (أو الإدارة الرئيسية) **الأكثر تكراراً** في صفوف التقرير الخاصة به (و«(غير محدّد)» عند غياب الاسم).
- **الموظف الملتزم:** موظف لا يحمل **أي مخالفة** في كل أشهره المراجَعة: لا استئذان > 4 ساعات (118/ب)، ولا أسبوع ≥ 60 دقيقة (118/ج)، ولا تجاوز 15 يوم غياب (خصم المكافأة).
- **نسبة الالتزام** = `(عدد الموظفين الملتزمين ÷ إجمالي الموظفين المراجَعين) × 100` لكل مجموعة.
- **الترتيب:** تصاعدياً بنسبة المخالفات = **الأكثر التزاماً أولاً**، مع `Rank` لكل مجموعة (1 = الأكثر التزاماً).
- **الاستجابة:** إجماليات عامة (`totalEmployees`, `compliantEmployees`, `violatingEmployees`, `overallCompliancePercent`, أيام 118/ب و118/ج، إجمالي دقائق التأخير، من تجاوز 15 يوماً) + `items[]` لكل مجموعة: `administration, rank, employees, compliantEmployees, violatingEmployees, compliancePercent, violationRatePercent, employeesOver4Hours, article118bDays, employeesOver60Minutes, article118cDays, weeklyLateMinutes, employeesExceeding15Days`.
- **الفلاتر:** `byMainDepartment` (true = الإدارة الرئيسية/المديريات «افتراضي»، false = الإدارة)، و`minEmployees` (عتبة أدنى عدد موظفين لتضمين المجموعة — تُبقي الإجماليات العامة على كل الموظفين).
- **ورقة Excel:** تُضاف «التزام الإدارات» كالورقة الثانية في `export-excel` (5 أوراق) مع سطر «الإجمالي العام» أسفل الجدول.


## تحليل «بصمات الحضور والانصراف» — المراجعة القانونية من البصمات الخام

> ملف «تقرير الحضور والانصراف» الخام (صف لكل موظف/يوم مع حالة التحضير وبصمتي الحضور والانصراف) هو **المصدر الحاسم** لاحتساب التأخير الفعلي؛ فبينما يعتمد تحليل «تقرير المغادرات» على الطلبات المُسجَّلة، يعتمد هذا التحليل على البصمات نفسها.

`POST /api/v1/punch/import` → رفع الملف إلى `StagingPunchRecords` • `POST /api/v1/punch/analyze` → التحليل القانوني والتخزين • `GET /api/v1/punch/export-legal-reports` → ملف Excel من **16 ورقة** • `GET /api/v1/punch/reports` → **قائمة تقارير الحضور والانصراف** (14 تقرير Excel مستقل) • `GET /api/v1/punch/calendar` → **تقويم العطل الرسمية والدينية** • واجهة: **`/punch.html`** (قائمة مستقلة لا تمسّ نظام المغادرات والإجازات).

### الاحتساب اليومي (من البصمات)

| المؤشر | القاعدة المطبَّقة |
| --- | --- |
| التأخير الصباحي | `max(0, وقت الحضور − 08:30)` — وإذا بلغ **15 دقيقة أو أكثر** (حدّ السماح القابل للتخصيص) يُحتسب «تأخيراً» للمادة 7 |
| الانصراف المبكر | `max(0, 15:30 − وقت الانصراف)` |
| المغادرة أثناء الدوام | مجموع الفجوات بين جلسات البصمة (انصراف ثم حضور لاحق) التي تزيد على **10 دقائق** |
| الغياب عن الدوام | `دقائق التأخير + الانصراف المبكر + المغادرة` بحدّ **420 دقيقة** (ساعات الدوام) |
| المادة 118/ب | إذا زاد «الغياب عن الدوام» في اليوم على **240 دقيقة** → خصم **يوم كامل من الرصيد السنوي** |
| المادة 118/ج | تجميع الدقائق خلال **أسبوع العمل (الأحد — الخميس)**؛ بلوغ **60 دقيقة** (قابل للتخصيص) → خصم **يوم كامل** (قابل للتخصيص) |
| المادة 7 | عدّ أيام التأخير شهرياً: `3` تنبيه خطي، `4` إنذار خطي، `>4` حسم **يومين من الراتب** |
| قاعدة الـ 15 يوماً | `غياب غير مبرّر + إجازة سنوية + مرضية + 118/ب + 118/ج > 15` → **خصم 50%** من المكافأة |
| المادة 112 | تراكم أيام الإجازة المرضية: `1–120` بأجر كامل، `121–240` بثلاثة أرباع، `241–360` بنصف الأجر |

### قواعد المعالجة وجودة البيانات

- **تصنيف الحالات العربية**: `مكتملة` / `غير مكتملة` (بلا انصراف) / `غياب` / `_` (لا بيانات) / `عطلة الأسبوع` / `عطلة رسمية` / `مغادرة` (سنوية، مرضية، تعويضية، وفاة، مهمة عمل، انتداب، تدريب، طارئ، طبي) بعد توحيد الهمزات والتاء المربوطة وإزالة العلامات الخفية (RTL) وتوحيد الأرقام العربية-الهندية.
- **دمج صفوف اليوم الواحد**: تُعتمد **أبكر بصمة حضور** و**أحدث بصمة انصراف**، وتُرجَّح الحالة الأعلى حكماً — لمنع ازدواج الاحتساب (اكتُشفت 664 حالة تكرار في ملف 2023-08-01→2024-01-11).
- **أيام `_` (بلا بيانات)**: تُستثنى من التحليل ولا تُحتسب مخالفة (20,626 يوماً في الملف المرجعي).
- **تقويم العطل المعتمد (جديد)**: أي يوم **عطلة نهاية أسبوع** (الجمعة والسبت — قابلة للتخصيص من `PunchAnalysis.WeekendDays`) أو **عطلة رسمية/دينية** (من كتالوج النظام المدمج أو من جدول `OfficialHolidays`) **لا يُحتسب غياباً ولا مخالفة**، حتى لو حمل في الملف حالة «غياب» أو بصمات فعلية؛ فالدوام في العطل يُصنَّف `WeekendWork`/`HolidayWork` ويُعرض للعلم (ساعات إضافية محتملة) ولا يدخل في مجاميع المادتين 118/ب و118/ج ولا في قاعدة الـ 15 يوماً.
- **الكتالوج المدمج للعطل (الأردن 2023 — 2025)**: العطل الرسمية (رأس السنة الميلادية، عيد العمال، عيد الاستقلال)، والعطل الدينية الإسلامية (رأس السنة الهجرية، المولد النبوي، الإسراء والمعراج، عيد الفطر، عيد الأضحى)، والعطل الدينية المسيحية (عيد الميلاد) — إضافةً إلى إمكانية إضافة/تعديل/استبعاد أي عطلة من واجهة «تقويم العطل» أو استيرادها من Excel.
- **الإجازات والاستئذانات**: تُحتسب أياماً بحسب نوعها، ومدّتها غير مدرجة في ملف البصمات.
- **المادة 118/ج — قاعدة أسبوعية مرنة (قابلة للتخصيص في وقت التشغيل)**: يُدمج (التأخير الصباحي + الانصراف المبكر + المغادرة أثناء الدوام) في **ناتج أسبوعي واحد**، وتُطبَّق بعدها القيمة السارية من **«إعدادات المادة 118/ج»** (واجهة الحضور والانصراف ← قسم 7، أو `api/v1/punch/analysis-settings`) بلا إعادة بناء ولا إعادة تشغيل:
  - **حدّ الدقائق الأسبوعي** (الافتراضي **60**)، والمخالفة عند **بلوغ** الحدّ أو **تجاوزه فقط** — بحسب الإعداد.
  - **سقف الناتج المحتسب** (اختياري: `0` = يتبع الحدّ) فلا يزيد المعروض/المُرحَّل إلى الملخص الشهري والمؤشرات عن السقف، وما زاد عليه لا يُضاعف خصم الأسبوع.
  - **أيام الخصم لكل أسبوع مخالف** (الافتراضي **1** يوم، ويقبل كسوراً مثل `0.5`).
  - **خيارات الدمج**: دمج/استبعاد الانصراف المبكر، ودمج/استبعاد المغادرة أثناء الدوام.
  - **اعتماد الناتج المحتسب أو المجموع الفعلي** في الملخص الشهري، و**حدّ السماح الصباحي** (المادة 7).
  - **حدود خاصة لإدارات محدّدة** (اسم الإدارة ← حدّ دقائق مستقل).
  - **معاينة الأثر قبل الحفظ** (`analysis-settings/preview`): مقارنة عدد الأسابيع المخالفة وأيام الخصم والناتج المحتسب بين النتائج المخزّنة والنتائج المتوقّعة، مع نماذج للأسابيع التي يتغيّر حكمها.
  - **تعطيل القاعدة كلياً** يوقف التجميع الأسبوعي والخصم مع إبقاء النتائج اليومية للتدقيق.
  - تُحفظ القيم في **`punch-analysis.json`** بجوار التطبيق (ملف مستقل تماماً عن `direct-source.json`)، والقيم الافتراضية تبقى في `appsettings.json → PunchAnalysis` (`WeeklyLateMinutesThreshold`، `CapWeeklyCountedMinutes`، `MorningGraceMinutes`) ويُعاد إليها بزر «إعادة الافتراضي». ويُسجَّل مع كل تحليل **بصمة القاعدة المطبَّقة ووقتها** (يظهر في قسم 7: «النتائج مطابقة للإعدادات» أو «أعد التحليل»).
  - يُحفظ العمودان معاً: `TotalMinutes` (المجموع الفعلي للتفصيل والتدقيق) و`CountedMinutes` (الناتج المحتسب بعد السقف)، وتُبنى كل التقارير والأوراق والملخصات من القيم السارية تلقائياً (أسماء الأوراق وترويسات الأعمدة ودليل القواعد وسطور المنهجية).
- **قيود معلنة في ورقة المنهجية**: عدم توفر أرصدة الإجازات وتواريخ التعيين، وضرورة تحديث التواريخ الدينية سنوياً من واجهة «تقويم العطل» عند صدور الإعلان الرسمي.

### الدوام المرن والعمل الإضافي (حسب قانون الخدمة المدنية — قابلة للتخصيص)

- **الدوام المرن**: يُسمح للموظف **المصرَّح له** بالحضور داخل نافذة معتمدة (`FlexibleEarliestArrival` — `FlexibleLatestArrival`، الافتراضي 07:30 — 09:30) وإكمال ساعات دوامه اليومية (`FlexibleCompleteDailyMinutes`، 0 = مدة الدوام الرسمي 420 دقيقة)؛ فتتحرّك **نهاية دوامه** بقدر تأخّره، فلا يُحتسب عليه تأخير صباحي داخل النافذة، ويُحتسب عليه الانصراف المبكر إن خرج قبل إكمال ساعاته، ويُسجَّل مقدار الحركة في `FlexibleMinutes`.
- **من يُطبَّق عليه؟** لا يُطبَّق إلا على من ورد في قوائم `FlexibleDepartments` / `FlexibleEmployees` أو لديه **تصريح دوام مرن ساري** في جدول `PunchWorkApprovals`، لأن `FlexibleRequireApproval = true` افتراضياً (فلا يغيّر النتائج القائمة بلا تصاريح). وبتعطيل الاشتراط وخلوّ القوائم يُطبَّق على الجميع.
- **العمل الإضافي**: يُحتسب ما يزيد على نهاية الدوام (أو على **نهاية الدوام المرن الفعّالة**) للموظفين المصرَّح لهم، بحدّ أعلى يومي `OvertimeMaxMinutesPerDay` (180 دقيقة = 3 ساعات) وحدّ شهري `OvertimeMaxMinutesPerMonth` (1200 دقيقة = 20 ساعة؛ 0 = بلا سقف) وأقل مدة تُحتسب `OvertimeMinMinutesPerDay` (30 دقيقة) وتدوير اختياري `OvertimeRoundToMinutes`.
- **لا عمل إضافي بلا موافقة مسبقة (الأصل)**: `OvertimeRequireApproval = true` افتراضياً، فلا يُحتسب أي عمل إضافي إلا لمن لديه **تصريح عمل إضافي ساري** في `PunchWorkApprovals` على ذلك اليوم، أو من ورد في قوائم `OvertimeDepartments` / `OvertimeEmployees` المعتمدة مسبقاً (تعميم/قرار إداري). وبذلك يظهر العمل خارج الدوام لمن ليس لديه موافقة كمدة **معلَّقة بانتظار تصريح** في اليومي (`OvertimeNeedsApproval`) والشهري (`OvertimeNeedsApprovalDays` / `OvertimeNeedsApprovalMinutes`) والإجمالي (`overtimeNeedsApprovalDays` / `overtimeNeedsApprovalMinutes`) وفي تقرير `overtime-flexible` (عمود «حالة الموافقة المسبقة»). وبتعطيل الاشتراط وخلوّ القوائم يُحتسب الإضافي للجميع وفق الحدود (سلوك ما قبل هذا الاشتراط).
- **تعويض التأخّر**: بخيار `OvertimeCompensateLateness` (افتراضياً نعم) تُخصم دقائق التأخير الصباحي من إضافي اليوم نفسه، فلا يُحتسب التأخير مرة تأخيراً ومرة عمل إضافياً.
- **أيام الراحة والعطل**: `OvertimeCountOnWeekends` / `OvertimeCountOnHolidays` (افتراضياً نعم) فتُحتسب **كامل** دقائق الدوام في نهاية الأسبوع والعطل الرسمية عملاً إضافياً، وكذلك دوام موظفي الورديات في أيام راحتهم/إجازاتهم.
- **نسب التعويض والساعات المعادلة**: `OvertimeRegularRate` (1.0) و`OvertimeWeekendRate` (1.5) و`OvertimeHolidayRate` (2.0) — تُنتج **الساعات المعادلة** لكل يوم (`EquivalentOvertimeMinutes`) وفي الشهر (`EquivalentOvertimeHours`) لاعتمادها في الصرف/التعويض.
- **الاحتساب الشهري**: تُجمع الدقائق لكل موظف عبر الشهر (`OvertimeMinutes` / `OvertimeHours`) مع تسجيل `RawOvertimeMinutes` (قبل التقييد) و`OvertimeExcludedMinutes` (المستبعدة بسبب الحدود أو عدم التصريح أو قِلّة المدة) و`OvertimeNeedsApprovalDays` / `OvertimeNeedsApprovalMinutes`، و`OvertimeCapReached` عند بلوغ الحدّ الشهري، إضافةً إلى `OvertimeWeekendMinutes` و`OvertimeHolidayMinutes`.
- **الموظفون المسموح لهم (التصاريح)**: جدول `PunchWorkApprovals` بتصريح لكل موظف بفترة سريان (من/إلى) ونوع (`Overtime = 1`, `Flexible = 2`) وحدّ يومي وإجمالي اختياريين وسند/ملاحظة وإيقاف بلا حذف؛ ويُدار من الواجهة (إضافة/تعديل/حذف/استيراد نصي) ومن `POST /api/v1/punch/work-approvals`.
- **التكامل مع تقرير العمل الإضافي القائم**: `POST /api/v1/punch/work-approvals/sync-overtime` يُرحّل إجمالي الساعات المحتسبة لكل موظف/شهر إلى جدول `OvertimeRecords` (قيد لكل شهر بتاريخ آخر يوم فيه) فيظهر في `GET /api/v1/reports/overtime` وفي عرض `v_punch_overtime_monthly`.
- **الإعدادات الافتراضية**: `PunchAnalysis.Flexible*` و`PunchAnalysis.Overtime*` في `appsettings.json`، وتُحفظ تعديلات وقت التشغيل في `punch-analysis.json` وتُدار من القسم 9 في `/punch.html` (أو عبر `PUT /api/v1/punch/analysis-settings` بحقلي `flexible` و`overtime`).
- **إلزامي**: أي تعديل على الإعدادات أو التصاريح يستوجب `POST /api/v1/punch/analyze` لتطبيقه على النتائج.
- **التحقق الآلي**: `powershell -ExecutionPolicy Bypass -File d:\TIME\data\verify_approval_rule.ps1` يفحص: تفعيل الاشتراط، صفر إضافي بلا تصاريح، حقول `overtimeNeedsApproval*` في الـ API، أعمدة/أسطر ملفات Excel، وعناصر الواجهة.

### تقويم العطل الرسمية والدينية (معتمد في التحليل)

- **المصدر المزدوج**: الكتالوج المدمج في النظام (`Audit/JordanHolidayCatalog.cs` — الأردن 2023 → 2025 بواقع 42 عطلة: 9 رسمية، 30 دينية إسلامية، 3 دينية مسيحية) + جدول `OfficialHolidays` (إضافات المشغّل، وهي **الأولوية** عند تطابق التاريخ).
- **أنواع العطل**: `1` رسمية (عامة)، `2` دينية إسلامية، `3` دينية مسيحية، `4` مناسبة وطنية.
- **أيام نهاية الأسبوع**: `PunchAnalysis.WeekendDays = [5,6]` (الجمعة والسبت) قابلة للتخصيص، و`PunchAnalysis.UseBuiltInHolidayCalendar` لتفعيل/تعطيل الكتالوج المدمج.
- **الاستبعاد**: حذف عطلة موجودة في الكتالوج المدمج يسجّل قيد «استبعاد» (`IsCancelled`) في `OfficialHolidays` يمنع اعتمادها، ويُستعاد بزر «استعادة كتالوج النظام» أو بإعادة إضافة التاريخ؛ أما العطل المُدخلة يدوياً فتُحذف فعلياً.
- **أثر التقويم على التحليل**: النتائج تُبنى مباشرةً من التقويم، لذا أي تعديل على العطل يستوجب إعادة تشغيل `POST /api/v1/punch/analyze`. وتُبقي حالات الملف التي تعلن «عطلة رسمية» اليوم عطلةً حتى لو لم تكن في التقويم (المصدر يعلنها)، بينما يُستثنى «الغياب» المسجّل في أي يوم عطلة من المخالفات.
- **إدارة التقويم من الواجهة**: إضافة عطلة واحدة، أو قائمة نصية (`التاريخ | الاسم | النوع`)، أو استيراد ملف Excel (أعمدة: التاريخ، الاسم/المناسبة، النوع)، أو استعادة الكتالوج المدمج، أو تنزيل تقويم العطل Excel.

### نظام الورديات وجدول الورديات الشهري (الحراسة وبقية الإدارات ذات الورديات)

- **الفكرة**: الإدارات التي تعمل بورديات متواصلة (مثال: الحراسة 24 ساعة متواصلة) لا تُقارَن أيامها بأوقات الدوام الرسمي (08:30 — 15:30)، بل بـ **جدول شهري** يصدره مسؤول الورديات ويُستورد إلى النظام.
- **الاستيراد**: `POST /api/v1/punch/shifts/import` يقبل ملف Excel بصيغتين: **شبكة شهرية** (عمود لكل يوم 1 — 31 يحمل رمز الوردية) أو **جدول طويل** (الرقم الوظيفي | التاريخ | الوردية | الساعات اختيارياً)، ويُحدَّد الشهر من الطلب أو من ترويسة الملف أو من مفتاح الفترة/اسم الملف.
- **رموز الجدول**: `ن/ل/ص/م/و` أو `24/12/8` = وردية دوام (بعدد الساعات)، `ر/ع/استراحة` = راحة، `إجازة/سنوية/مرضية/طارئة/حج/زواج/وفاة` = إجازة، `عطلة رسمية/عيد` = عطلة، `دورة/تدريب/مهمة` = دورة، و`-` أو الخانة الفارغة = لا قيد. أي رمز آخر يُعامل «يوم وردية دوام» ويُظهر رمزه في ملاحظات اليوم للمراجعة.
- **حالة اليوم في التحليل**: تُوسم أيام الجدول بحالات جديدة (`18` وردية دوام، `19` راحة، `20` إجازة، `21` عطلة، `22` دورة) لا تُقارَن بأوقات الدوام الرسمي، ولا تُحتسب الراحة/الإجازة/العطلة غياباً.
- **الاستثناء الافتراضي**: العاملون بالورديات يُعفون من المادة 118/ج (للأسابيع المشمولة بجدولهم الشهري فقط) ومن التأخير الصباحي (المادة 7) والانصراف المبكر — وكل خيار قابل للتخصيص في وقت التشغيل.
- **ما يبقى مرصوداً**: وردية دوام بلا أي بصمة تُلاحَظ بعبارة «تُحال إلى مسؤول الورديات للمراجعة»، ويمكن تحويلها إلى غياب بخيار `ShiftMissingPunchIsAbsence`.
- **استثناءات الإدارات/المديريات الخاصة (عدة مديريات)**: لكل إدارة استثناء مستقل يشمل أيّاً من: إعفاء من 118/ج، إعفاء من التأخير الصباحي، إعفاء من الانصراف المبكر، إعفاء من احتساب الغياب/118/ب، حدّ أسبوعي خاص، سقف خاص، معاملة بنظام الورديات، وسند الاستثناء للتدقيق. مطابقة اسم الإدارة **مرنة** (توحيد الهمزات والتاء المربوطة والمسافات + احتواء الاسم أحدهما للآخر).
- **إدارة الجدول**: `GET /api/v1/punch/shifts` (المؤشرات + دفعات الاستيراد + عيّنة القيود)، `GET /shifts/template?year=&month=&department=` (قالب Excel جاهز للتعبئة + دليل الرموز)، `GET /shifts/export?batchKey=` (كشف الجدول المستورد)، `DELETE /shifts/batches/{id}` (حذف دفعة استيراد كاملة).
- **إعادة الاستيراد**: `replace=true` يستبدل كل قيود الفترة المستوردة، و`replace=false` يستبدل قيود الموظفين الواردين في الملف فقط.
- **الأثر**: أي تعديل على الجدول أو الاستثناءات يستوجب `POST /api/v1/punch/analyze` (زر «إعادة التحليل بالجدول» في الواجهة).
- **الإعدادات الافتراضية**: `PunchAnalysis.ShiftSystemEnabled / ShiftCycleHours / ShiftExemptFromWeeklyRule / ShiftExemptFromMorningLateness / ShiftExemptFromEarlyDeparture / ShiftRestDaysNotAbsence / ShiftMissingScheduleExempts / ShiftMissingPunchIsAbsence / ShiftDutyGraceMinutes / ShiftDepartments` في `appsettings.json`، وتُحفظ تعديلات وقت التشغيل في `punch-analysis.json`.

## الربط المباشر بقاعدة البيانات (بلا ملفات Excel)

عند تفعيله من زر **⚙️** في الواجهة، تُسحَب صفوف «تقرير المغادرات» **مباشرة من قاعدة بيانات** (قاعدة النظام `AttendanceAudit` أو خادم SQL Server خارجي)، ثم تُستورد إلى `StagingDeparturesReport` عبر **نفس منطق تحويل الأعمدة العربية** المستخدم في ملف Excel، وتُراجَع قانونياً (118/ب + 118/ج + قاعدة المكافأة) وتظهر نتائجها في اللوحة — **دون رفع أي ملف**.

**وضعا الاتصال (`mode`):**

- `app` — قاعدة بيانات النظام الحالية (`ConnectionStrings:DefaultConnection`)، بلا بيانات اعتماد إضافية (يُعرَض اسم القاعدة في النافذة).
- `ext` — خادم SQL Server خارجي: `server` + `database` + `auth` (`windows` أو `sql` مع `userId`/`password`)، أو **`connectionString` كاملة** تتجاوز الحقول أعلاه.

**الاستعلام (`query`):** استعلام قراءة **واحد** يُرجع صفوف التقرير بالأعمدة العربية نفسها (أو بالترتيب نفسه `0..12` إن اختلفت الأسماء):

```sql
SELECT TOP (50000) *
FROM dbo.DeparturesRequests;
```

- يُقبَل `SELECT`/`WITH` فقط (تُنظَّف التعليقات أولاً، ويُرفض أي استعلام متعدد العبارات أو يحتوي أوامر تعديل) — المصدر **قراءة فقط**.
- القراءة **بثّية** (`SequentialAccess`) صفاً صفاً مع حد أقصى `maxRows` (افتراضي `100000`) ومهلة `commandTimeoutSeconds` (افتراضي `300`, المسموح `15..3600`)، ويُعلَّم التنبيه `truncated` عند الوصول إلى الحد.
- **حماية بيانات اللوحة:** لا يُفرَّغ جدول المرحلة إلا **بعد نجاح قراءة أول صف صالح من المصدر**؛ فإن فشل الاتصال/الاستعلام أو أرجع صفر صفوف تبقى نتائج المراجعة السابقة كما هي (مع تنبيه في رسالة المزامنة). وينطبق الأمر ذاته على رفع ملف Excel بلا صفوف صالحة.

**الأتمتة:** `autoSyncOnLoad` (مزامنة عند فتح اللوحة — مفعّل افتراضياً) و`autoSyncMinutes` (مزامنة دورية كل عدد دقائق، `0` = معطّلة) و`replaceExisting` (استبدال جدول المرحلة قبل الاستيراد، أو الإضافة إليه) و`sourceLabel` (اسم يظهر في اللوحة والتقارير).

**كلمة المرور:** تُخزَّن **مشفَّرة بـ Windows DPAPI** (نطاق الجهاز + مفتاح خاص بالتطبيق) في ملف الإعدادات، ولا تُعاد إلى المتصفح إطلاقاً (تُرسَل فقط راية `hasPassword`، وتُخفي النافذة كلمة المرور داخل سلسلة الاتصال الكاملة بـ `Password=••••••`). وعند تعذّر DPAPI تُخزَّن `Base64` مع تنبيه في السجل.

**ملف الإعدادات:** `AttendanceApi/direct-source.json` (يُعاد إنشاؤه عند أول حفظ، ويُعرَض مساره في النافذة للنسخ الاحتياطي) — ويحوي `settings` + `state` (آخر مزامنة: الوقت/الرسالة/عدد الصفوف/الزمن). ويمكن تعديله يدوياً: الخادم **يعيد قراءته تلقائياً عند تغيّره على القرص** (أو حذفه) دون إعادة تشغيل.

**أمثلة:**

```bash
# تفعيل الوضع على خادم خارجي بمصادقة SQL مع مزامنة كل 30 دقيقة
curl -X PUT "http://localhost:5000/api/v1/settings/direct-source" -H "Content-Type: application/json" \
  -d '{"enabled":true,"mode":"ext","server":"10.0.0.5,1433","database":"HR","auth":"sql","userId":"sa","password":"******","query":"SELECT TOP (100000) * FROM dbo.DeparturesRequests","autoSyncMinutes":30}'

curl -X POST "http://localhost:5000/api/v1/settings/direct-source/test"          # اختبار الاتصال
curl -X POST "http://localhost:5000/api/v1/settings/direct-source/preview?take=5" # معاينة الأعمدة
curl -X POST "http://localhost:5000/api/v1/settings/direct-source/sync"           # مزامنة الآن
curl "http://localhost:5000/api/v1/departures/review-summary"                     # ملخص اللوحة الحالي
curl -X POST "http://localhost:5000/api/v1/settings/direct-source/disable"        # تعطيل الوضع
```

> نتائج المزامنة تُحفظ: عند إعادة فتح اللوحة في وضع الربط المباشر تُعرض آخر نتائج محفوظة (`review-summary`) فوراً، ثم تُحدَّث تلقائياً بحسب `autoSyncOnLoad`/`autoSyncMinutes`.


## تنظيف البيانات — استقبال بيانات جديدة (زر واحد في اللوحة)

شاشة مستقلة في اللوحتين (`punch.html` و `index.html`) ضمن مجموعة **«الصيانة والبيانات»** في القائمة اليمنى،
ويُتاح الوصول إليها أيضاً من زر **«🧹 تنظيف البيانات»** في الشريط العلوي (ظاهر من كل الشاشات) ومن الواجهة الترحيبية.

**ما تفعله الشاشة:**

1. تعرض — قبل التنفيذ — جدولاً بكل جدول في قاعدة البيانات: اسمه ووصفه العربي وعدد صفوفه الحالي وحالة الإجراء عليه (`سيُحذف` / `يُحفظ`).
2. خياران للنطاق:
   - **بيانات التشغيل والتحليل** (`data` — الموصى به): تفريغ `StagingPunchRecords` و`PunchDailyResults` و`PunchWeeklyResults` و`PunchMonthlyResults` و`PunchWorkApprovals`، و`ShiftScheduleEntries`/`ShiftScheduleBatches`، و`StagingDeparturesReport` و`DeparturesReportReviews` و`DeparturesWeeklyLateness` و`Departures` و`DepartureWeekAggregates`، و`AttendanceRecords`/`StagingAttendance` و`LeaveRequests`/`LeaveBalances`/`SickLeaveDetails`، و`DisciplinaryActions`/`MedicalCommitteeDecisions`/`OvertimeRecords`/`EndOfServiceCompensations`، و`AuditRunLogs` — **مع الإبقاء** على البيانات المرجعية (الموظفون، الإدارات، الفئات الوظيفية، جداول الدوام، أنواع الإجازات، العطل الرسمية) وعلى كل إعدادات المنظومة.
   - **مسح شامل** (`all`): ما سبق + الجداول المرجعية + أي جدول آخر موجود في قاعدة البيانات (يُعرض باسم «جدول إضافي غير مصنَّف»).
3. خيار إضافي: **إعادة إعدادات المادة 118/ج إلى القيم الافتراضية** (`appsettings.json`) — بحذف `punch-analysis.json`.
4. زر **«🔍 معاينة بلا حذف»**: يُنفِّذ مسار التنظيف داخل معاملة (بحذف **عيّنة محدودة** — حتى 500 صف من كل جدول) ثم يُلغيها — لعرض عدد الصفوف التي ستُحذف دون أي تغيير فعلي، وبلا انتظار طويل على الجداول الضخمة.
5. زر التنفيذ مقيَّد بكتابة كلمة **«حذف»** في حقل التأكيد (تُتحقَّق في الواجهة وفي الخدمة معاً).

**ضمانات التنفيذ:**

- الحذف يتم داخل **معاملة واحدة (Transaction)** مع تعطيل قيود المفاتيح الأجنبية مؤقتاً ثم إعادة تفعيلها **مع التحقّق** (`WITH CHECK CHECK CONSTRAINT ALL`)، وتصفير عدّاد الهوية (Identity) للجداول المُفرَّغة — فلا حاجة لترتيب حذف معيّن. ويُستثنى من ذلك **«المعاينة بلا حذف»**: تُحذف فيها عيّنة محدودة من كل جدول فقط (بلا تصفير عدّادات ولا إعادة تحقّق من القيود)، لأن إلغاء المعاملة يعيد كل شيء كما كان — ولهذا تبقى سريعة على أي حجم بيانات.
- **لا يُحذف المخطط**: الجداول والـ Views والإجراءات المخزّنة (`sp_process_year_end_rollover` …) وملفات الإعدادات (`appsettings.json` و`direct-source.json` و`punch-analysis.json`) تبقى كما هي.
- **تصفير بصمة آخر تحليل**: تُصفَّر `lastAnalyzedAtUtc`/`appliedRule` في `punch-analysis.json` (بلا حذف القاعدة المحفوظة) ليعود النظام إلى حالة «لا نتائج بعد» وتُفرَّغ لوحة المؤشرات تلقائياً.
- **حماية أثناء العمل**: يُرفض التنفيذ بـ `409 Conflict` إذا كانت دورة مراجعة قيد التشغيل (`audit-status.isRunning`)، وبـ `400 Bad Request` إذا غابت كلمة التأكيد.
- بعد نجاح التنفيذ تُعاد شاشة الرفع إلى حالتها الأولى وتُحدَّث اللوحة، مع ملخص النتيجة وملاحظاته وقائمة الجداول المُفرَّغة.

```bash
# 1) حالة البيانات الحالية (ما سيُحذف وما سيبقى)
curl "http://localhost:5000/api/v1/maintenance/data-status"

# 2) معاينة بلا حذف (حذف عيّنة من كل جدول داخل معاملة ثم إلغاؤها)
curl -X POST "http://localhost:5000/api/v1/maintenance/reset?dryRun=true" \
     -H "Content-Type: application/json" \
     -d "{\"scope\":\"data\",\"confirm\":\"حذف\",\"resetWeeklyRule\":false}"

# 3) التنفيذ الفعلي (تنظيف بيانات التشغيل والتحليل)
curl -X POST "http://localhost:5000/api/v1/maintenance/reset" \
     -H "Content-Type: application/json" \
     -d "{\"scope\":\"data\",\"confirm\":\"حذف\",\"resetWeeklyRule\":false}"

# 4) مسح شامل (كل شيء من الصفر — يشمل الموظفين والإدارات والعطل وأنواع الإجازات)
curl -X POST "http://localhost:5000/api/v1/maintenance/reset" \
     -H "Content-Type: application/json" \
     -d "{\"scope\":\"all\",\"confirm\":\"حذف\",\"resetWeeklyRule\":true}"
```

> **التحقق الآلي:** `powershell -ExecutionPolicy Bypass -File d:\TIME\data\verify_maintenance.ps1` — يفحص نقطة الحالة، ورفض التنفيذ بلا تأكيد، والمعاينة بلا حذف (مع التأكد من عدم تغيّر أعداد الصفوف)، وشاشة التنظيف في اللوحتين. والفحوص الحيّة فيه **لا تحذف أي صف**.
